## 页面定位

**操作页。** 每张卡 = 一项游戏内操作。所有会真实消耗资源（士兵 / 体力 / 金币 / 道具）
的动作都在这里，所以本页的重点不是好看，而是**别让人误操作**。

---

## 布局

- 两列 `.grid.g2`（≤820px 转单列），按"日常 / 联盟 / 高级"分节，节标题用 `.sec`
- 每张卡的结构固定：

```
<h2> 标题 + 副标题(.sub 协议名) + 汇总(.sumline) + 折叠按钮
  主按钮行     1 个 primary + 若干次级按钮
  选项行       自动开关（复选框），开关状态要落库
  说明         .hint —— 说清消耗什么、默认行为是什么
  结果条       .res —— 上一次操作结果，刷新页面后仍在
```

- 副标题带协议名（`everydayexchange + userpayreward`），是排查问题时唯一线索，**不要删**
- 长说明放 `.hint`，超过 3 行就折叠进 `<details>`（如"查看面板明细（13 项）"）

## 本页专属规则

### 主按钮

- 一张卡最多一个 `.primary`。多个等价动作并列时，第一个是主，其余用次级样式
- 主按钮文案写**具体动作**："一键完成"、"一键领取"、"开始打怪"，不要写"确定"/"执行"

### 危险与消耗

- 会消耗资源 / 不可撤销的动作 → `askConfirm()`，并且 `confirmText` 写清后果
  （"开始打怪"、"发起集结"、"分派"，不是"确定"）
- 提示正文写**真实代价**（几队并行、几个兵、会不会踢 App 下线），不要写"确定吗？"
- `kind` 选择：只是花资源 → `'warn'`；删账号/删用户 → `'danger'`

### 开关

- 自动执行类开关（自动签到、可领时自动领）默认**关**，且必须写清触发条件
- 有代价的开关（连消耗项一起跑）默认**关**，并在 `.hint` 里说明代价由谁承担
- 开关状态走后端持久化（`saveSetting`），不能只存在 localStorage

### 结果反馈

- 每次操作都要留结果条 `.res`（`ok`/`err`/`warn`），内容是**具体结果**：
  "加速成功 · 加速石×2"，不是"操作成功"
- 失败要把原因写出来（错误码 + 错误文本），别只写"失败"
- toast 用来提示，`.res` 用来留痕，两者都要有
